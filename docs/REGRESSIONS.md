# Regression ledger

Every bug found becomes a check, so it cannot come back. One row per issue, newest last. See [`CONTRIBUTING.md`](../CONTRIBUTING.md) for the rule.

| Issue | What went wrong | The check that now prevents it |
| --- | --- | --- |
| #167 | GitHub Actions were referenced by movable tags, which can be repointed at different code. | Every action is pinned to a full commit SHA, and the `lint-workflows` workflow (zizmor) fails on unpinned actions. |
| #168 | A float was serialised beside the decimal text in hashed readings, so the hash could differ between machines. | The golden test `canonical_json_is_pinned_and_has_no_float` in `crates/sawbones-reading/src/reading.rs` pins the exact canonical JSON and asserts it contains no float. |
| #168 | A public `trust` field let any code choose its own trust tier. | The `compile_fail` doctest on `Reading` in `crates/sawbones-reading/src/reading.rs` fails the doc tests if `reading.trust` ever becomes assignable from outside the crate. |
| #187 | The value of a write never affected the class and had no limit, so a write-map entry could not refuse an out-of-range value. | `regression_187_*` tests in `crates/sawbones-policy/tests/regression_187.rs`: an entry's optional `ValueRange` (carrying the entry's tier) refuses out-of-range writes with `ValueOutOfRange`, and entries with no range behave as before. |
| #187 | Code could copy outside text into an `Ident` through `WorldText::as_untrusted_str` and use it as a port or signal name. | `regression_187_world_text_cannot_become_an_identifier` in the same file: `PortId` and `SignalId` are built only from 1 to 64 bytes of `a-z 0-9 _ -` starting with a letter, so instruction-shaped or out-of-set text is rejected. |
| #199 | The regression guard ignored `fix`, `fixed`, `closed`, `resolve` and other closing keywords, accepted a comment as the check, ignored deleted tests, and could be edited by the PR it judged. | `ci/regression_guard.py` recognises every GitHub closing keyword, needs a changed Rust test fn (or CI step) naming `regression_<N>`, and fails deleted tests, `#[ignore]` and removed CI steps and its own edits without the `guards-change` label. `regression_199_*` tests in `ci/test_regression_guard.py` run in the `regression-guard` workflow, which judges PRs with the base branch copy of the guard. |
| #200 | A PR could weaken `deny.toml`, a workflow, the guard or `CLAUDE.md` and be judged by the weakened version. | The `protected-paths` workflow (`.github/workflows/protected-paths.yml`, #200) lists changed protected files and fails unless the PR has the `guards-change` label; those PRs need the clean-room reviewer. |
| #208 | Compiled Python caches (`ci/__pycache__/*.pyc`) were committed in a PR. | `.gitignore` ignores `__pycache__/` and `*.pyc`, and the `no build output committed (#208)` job in `ci.yml` runs `ci/no_build_artifacts.sh` (`regression_208_no_build_artifacts`), failing if any tracked file is build output. |
| #202 | `WorldText::fenced` left variation selectors, invisible fillers (Hangul, Braille, Khmer, combining grapheme joiner), and fullwidth or look-alike angle brackets and fence characters raw, and the length cap counted bytes before escaping. | `regression_202_*` tests in `crates/sawbones-reading/src/world_text.rs`: every class is escaped as `\u{hex}`, the whole Unicode default-ignorable set is checked, forged look-alike fences stay inside one line, the cap counts escaped bytes, and a seeded fuzz loop asserts a fence never has extra newlines. |
| #203 | Nothing proved that the Modbus frame the bus guard passed encoded the action the policy engine classified (a confused-deputy encoder, bus-014); write maps and digests had no unit address, so paralleled inverters on one bus collided (bus-016); the window between the guard's decision and transmission was not enforced by types (bus-009); and mastership was declared but never observed on the wire (bus-020). | `regression_203_*` tests in `crates/sawbones-modbus-encode/tests/encode.rs` (one shared encoder: golden frames and digest, refusals, randomised round trips), `crates/sawbones-busguard/tests/regression_203.rs` (exactly the approved action's frame passes and every one-byte change is blocked; a lease for one unit never passes another; a grant whose digest is not its action's is refused; `Pass` owns the checked bytes and `GuardedLine` sends only a `Pass` for its port, with `compile_fail` doctests against raw slices and double sends; a foreign request blocks writes until a new allow-list, while the guard's own echo does not) and `crates/sawbones-policy/tests/regression_203.rs` (units in entries, requests and digests; the policy decision, the interlock lease, the signed approval and the guard lease carry one digest end to end). |
| #197 | A latched fault lived only in RAM, so a brownout or watchdog reset forgot it and the arm switch alone re-armed. `ClearFault` carried no provenance, so the supervisor could clear a fault. | `regression_197_*` tests in `crates/sawbones-interlock/tests/rules.rs` and `tests/serde.rs`: a restart reads a persisted `FaultRecord` and comes up with `FaultStateUnknown` latched unless the record is clean, a recorded fault survives a power loss, a clear needs a `PanelToken` with the button sensed, a supervisor clear is refused in every state, and a panel token never deserialises. The randomised oracle in `tests/invariants.rs` checks that no rail comes on after an unproven restart without a panel clear. |
| #198 | The supervisor reported `heartbeat_healthy` as a boolean it could fake, replay or feed from a stuck task. | `regression_198_*` tests in `crates/sawbones-interlock/tests/rules.rs`: the interlock issues a challenge each period from a boot nonce, and a wrong, stale, early, repeated, missing or cross-boot reply, or a stalled step loop, latches `HeartbeatLost`; nothing arms without a correct reply; rails drop within two periods of the last good reply. The exhaustive grid and the randomised oracle in `tests/invariants.rs` check that no rail is on without correct replies. |
| #198 | `State::POWER_ON` started its heartbeat watch with a nonce of 0, so its challenges were fixed and predictable until the firmware fed a restart. | The watch has an explicit not-started state (`nonce: None`, `HeartbeatWatch::NOT_STARTED`) until an `Event::Restart` brings a hardware nonce; the restart's nonce is an `Option<NonZeroU64>`, and `None` (no nonce from the generator) leaves it not started (#114: no zero sentinel). Then there is no challenge, every reply is a loss, and nothing arms or clears. `regression_198_no_heartbeat_before_restart` in `crates/sawbones-interlock/tests/rules.rs`, and the not-started invariants in the exhaustive grid in `tests/invariants.rs`. |
| #214 | A signal's register width came from the value's type, so an entry with no range accepted a two-register value into a one-register signal and overwrote the register next to it (bus-015, bus-017). | `regression_214_*` tests: `crates/sawbones-policy/tests/regression_214.rs` (each write-map entry states a width of 1 or 2 and has no default; a value of any other width is refused with `WidthMismatch`, with or without a range, before the range check), `crates/sawbones-modbus-encode/tests/encode.rs` (`BusWriteAction::new_with_width` refuses a register count that differs from the width; the action and digest are unchanged for a matching one) and `crates/sawbones-busguard/tests/regression_214.rs` (a frame with another register count never spends the lease, and a rule sized to the width blocks a wider frame).
